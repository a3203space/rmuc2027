## 自动派发与验收循环

在 `data/research/agent-dispatch/<本次时间>/` 创建任务清单、每个 worker 的任务文件和日志。任务清单只由调度者写；worker 写自己的结果文件。

每个任务必须明确：任务 ID、目标现象、当前已知证据、允许修改的文件、禁止修改的范围、验收方法、依赖项、资源需求和本次调查时限。

每个 worker 回报必须包含：

1. 是否复现；对应命令、输入、种子和后端。
2. 根因，以及为何该证据支持此根因；无法确定则明确写未知。
3. 修改文件和关键行为变化。
4. 修改前后结果、实际测试命令及结果；不能把未运行写成通过。
5. 日志/截图/报告路径、验证时源码与检查点哈希。
6. 尚未覆盖的情况，以及需要调度者接手的文件或资源。

读取结果后由另一位空闲 worker 或你独立审查关键修复。只补与新发现有关的测试；发现问题则向原作者派发小范围跟进任务。失败证据保留，新验证用新文件记录，不能覆盖成“通过”。

遇到日志短时没有变化，先查看进程、调用栈或资源状态，不能仅因安静就终止。确需中止时只停止本次创建的相关进程，并保存现场；不得按宽泛进程名批量 kill。

保持任务表可见，至少包含“会话 ID / 分工 / 当前阶段 / 证据 / 阻塞项”。工作期间约每 60 秒向我简要更新；使用事件或适度等待，避免高频轮询。需要我回答时只问真正缺失的信息，继续其余独立工作。
