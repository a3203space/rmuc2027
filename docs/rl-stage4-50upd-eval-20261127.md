## 五、24 局回放深度审计与下一阶段（Stage-5）高价值优化点

对全部 24 份 Rapier 回放与 `*-actions.jsonl` 动作轨迹完成逐帧审计后，确认了以下工程结论与明确残余问题：

### 已验证彻底生效的改进
1. **零微速爬行、零不可达**：24 局共 `20,160` 个 RL 决策步中，策略模式微速爬行步（`0.03 < move < 0.20`）为 **`0`**，`unreachable` 为 **`0.00 s`**。
2. **交火姿态防自杀生效**：全部 27 次阵亡中，21 次处于 `defense`、5 次处于 `attack`，仅 1 次处于 `move`（`1007-blue` 在 280 血转场时遭集火秒杀），彻底消灭了 Stage-3.5 因交火切 `move` 姿态被锁死 5 秒的典型死法。
3. **10 Hz 火力完全释放**：交火热量充分利用 `240–259/260` 区间，零过热惩罚（`overheated = False`）。

### 审计发现的 3 个精准残余瓶颈（供 Stage-5 针对性优化）
1. **Rapier 刚体物理中的两处长卡顿（占全部 16 次 `>=4 s` 卡顿的 100%）**：
   - `1000-red`（`opus55_team`，`recover = 226.4 s`）：低血（120 HP）处于 `defense` 姿态撤退经红方道路减速带 `(6.20, 13.20)` 时，位于现有 `_recover_nav_goal` 绕行框（`lx <= 5.25`）以东，反复在减速带卡滞，直接葬送本可取胜的对局。
   - `1009-red`（`dsv41_1017_heavy`，`recover = 247.5 s`）：在 `t = 198.5 s` 卡在中央高地边缘台阶 `(16.85, 10.60, z=0.43)` 发生底盘托底悬空（`v = (0, 0)` 持续 221.5 s），`warp_kinematic` 运动学近似不会出现该托底现象，属于典型 Sim-to-Sim 物理差异。
2. **偏激进交火导致 Rapier 阵亡偏高（27 死 / 24 局，局均 1.13 死）**：
   - `1013-red / 1013-blue`（`dsv41_1017_sentry`）在 `warp_kinematic` 以 `423-0 (0 死)` 完胜，但在 Rapier 中 `0-2` 落败且阵亡 5 次（多次在中场被敌方英雄 42 mm 连发两炮 `400 → 200 → 0` 秒杀），`gemini38_2027_hunter` 亦因中场阵亡 5 次 `0-2` 落败。后续可在微调阶段适度提高 `death` 惩罚（如 `-0.5 → -1.0`）并延续训练至 `u80–u100`。
3. **`dsv41_1017_pair` 偷卡对策需更长程策略探索**：
   - 相比 Stage-3.5，`u50` 已在 `warp_kinematic` 将对阵 `pair` 的控制分差收窄近半、训练期取得 13–21% 胜率，且在 Rapier 蓝方压低敌方基地血量至 `9730`；若在修复上述两处 Rapier 地形脱困后继续用较低学习率（如 `1.5e-4`）续训，有望进一步突破 `pair` / `hunter` / `sentry`。
