# RMUC 2027 局域网游玩

构建步骤见根目录 [README](../README.md)。所有命令从项目根目录执行。

## 黑屏排查

操作手 HUD 和三维画面位于同一 WebEngine 页面，三维画面使用 OpenGL / WebGL 2。Qt 6.2 使用软件场景图时会关闭 WebEngine GPU 路径，无法显示三维画面。三维初始化失败时页面显示原因，战术 HUD 仍保留；客户端终端的 `ARENA_WEB` 日志记录页面错误与渲染状态。

若终端出现 `Failed to create a WebGL2 context`，先确认已重新编译最新版客户端，并检查 `QT_QUICK_BACKEND`、`QT_OPENGL` 和 `QTWEBENGINE_CHROMIUM_FLAGS`。不要将 Qt Quick 设为 `software` 或给 Chromium 传入 `--disable-gpu` / `--disable-webgl`。修改环境变量后需完全退出客户端再启动。

若血量与地图正常、中央没有画面，查看 `ARENA_CAMERA_STATE`（场地/相机是否就绪）、`ARENA_CANVAS_READY`（画布是否初始化）和 `ARENA_RENDER_TIMING`（是否持续渲染）。超过 3 秒未输出渲染帧时会显示恢复提示，可点击“重新加载画面”。若客户端的“仿真目录”为 `build/runtime/app`，只构建根目录前端不会更新运行包；需同步或重新准备运行包，并重启房主进程。

## 建房和加入

启动 `RMUC2027Client`。房主填写本工程根目录或准备好的运行包目录，点击“创建房间”；其他玩家填写房主局域网 IP 和端口 `8766`，点击“加入房间”。独立运行主机时，房主需填终端输出的 `owner_key`，普通玩家留空。

每人选择一个红/蓝方席位，步兵可在准备前选择血量/功率和冷却/爆发性能。全部真人准备后由房主开局，空位由所选 AI 策略补齐。

| 操作 | 输入 |
| --- | --- |
| 移动、瞄准、射击 | WASD、鼠标、左键 |
| 3 号轮腿 | W/S 前后，A/D 转向，鼠标独立控制云台 |
| 加速、跳跃、下蹲 | Shift、Space、Ctrl，按机器人能力执行 |
| 折叠 / 展开 | F，仅支持变形的型号 |
| 释放鼠标、打开操作菜单 | Esc；关闭菜单后点击三维画面恢复鼠标 |
| 展开战术地图与双方详细状态 | 按住 Tab，松开恢复 |
| 重装 | 拾取、装配辅助、安装发射机构；手动移动取消辅助 |
| 机库 | 选择目标、起飞攻击、召回；不提供无人机相机 |
| 哨兵 | 驾驶射击、姿态切换；手动控制属于仿真游玩扩展 |
| 补给、回血、复活 | Esc 菜单中的角色按钮，显示费用和不可用原因，由主机判定 |

## 操作手界面

- 顶部显示双方基地、前哨站当前/最大血量、护盾、重建状态、基地保护、控制度、经济与剩余时间。
- 顶部第二行显示四个控制位置、完全/临时控制、占领或释放计时，以及关联的八个激活区。进度来自主机秒数；双方争夺时显示暂停状态。
- 左右列显示双方机器人存活与血量；按住 Tab 查看弹药和公开增益。左下地图保留场地多边形、控制区、高地、堡垒等区域，展开后可查看完整区域列表。
- 右下显示自身热量、功率、缓冲能量、后勤、弹药配送和复活进度。重装另有装配和发射机构状态；哨兵显示姿态和冷却；机库显示无人机状态。
- 中央瞄准使用原客户端三张准星素材。菜单中的按钮按当前角色提供，房间与灵敏度设置从“房间与设置”进入。
- 开局后原生房间面板自动收起。比赛结束显示结算菜单，可保存回放、准备并由房主开始下一局。

连接中断或超过 2.5 秒没有快照时停止输入，并标记最后一帧为过期数据。操作回执表示主机控制器已接收；实际购买、回血、姿态等效果以随后主机快照为准。

结算页面显示控制度、击毁、伤害与实际机器人数据，支持查看 MVP、保存回放、重新配置和准备下一局。

250 ms 无新输入时停止手动运动与射击；断线 3 秒后 AI 接管，席位保留 30 秒。重连需显式恢复控制。房主退出关闭房间。

双方雷达解波始终成功，地图和面板显示规则允许的战术情报；第一视角仍受视场和遮挡限制。过热断图传，基地受损降低图传清晰度，黄牌遮挡图传、地图和战术 UI。

## 机库、策略与同步入场

进入“机器人机库”，先选红/蓝方与席位，再选实际型号。真人只能修改自己的席位，房主可修改 AI 空席位；双方硬件可以不同。型号会同时改变物理底盘、机构和外观。轮足、串联腿、折叠麦轮等能力在机库参数和动态演示中展示。变形型号使用 **F** 折叠/展开，也可通过 Esc 菜单操作；展开受隧道屋顶限制。

“策略库”可以为每个席位选择型号兼容的单机策略，或由房主为队伍启用全队策略。全队策略覆盖该队 AI 席位，真人输入优先。全队策略的固定阵容必须与该队实际型号一致；不兼容的选项不可应用。切回“使用逐机器人策略”后恢复各席位配置。真人断线时也使用所选策略接管。

内置策略目录包含 94 个 2027 策略包和通用基线，不依赖研究模块。房主点击“导入本地策略包”，选择包含 `manifest.json` 的目录；对应 Python 文件及可选的 profile/showcase 元数据由主机验证后保存到用户数据目录，版本不可变。策略以本地子进程运行，应由房主导入自己信任的代码；无需 Docker。策略错误和超时会保存在回放诊断中。

修改型号或策略会清除所有准备状态。开赛后配置锁定，晚加入玩家继承该席位现有型号。开局依次经过资源准备、原 Arena 风格逐机器人介绍和 5 秒倒计时；这段时间引擎 tick 和比赛计时均为 0。资源准备等待所有真人客户端完成模型加载与首帧渲染，最多 60 秒；失败或断线返回大厅。房主可跳过约 38.3 秒的介绍，所有人统一进入倒计时。重连按主机当前进度恢复，不重播整段介绍。

本版使用联机协议 **v2**。客户端启动时通过仅监听回环地址的本地临时 HTTP 服务读取界面、模型和可寻址音频，加入时检查主机资源版本。此临时端口不对局域网开放。`cmake --build --preset release` 会自动构建前端并复制到客户端旁的 `web/`；发行客户端必须携带此目录。主机包内的 `app/build/web` 也必须同步，不能混用旧版运行包。

## 回放

比赛结束后点击“保存本局回放”。本地查看：

```bash
uv run --locked rmuc2027 replay data/replays/某局.json
```

打开终端输出的本地地址。查看器支持播放本局入场介绍、暂停、拖动和自由观察；大回放由服务端建立帧索引、分批读取，不一次载入整局。页面可直接选择小于 64 MiB 的本地文件，更大的文件使用上述命令。

```bash
uv run --locked rmuc2027 verify-replay data/replays/某局.json
```

确定性校验要求记录回放的引擎版本与当前版本一致。历史 2027 回放仍可播放，跨版本不会被冒充为校验通过。

## 可搬移主机包

```bash
uv python install 3.12
uv run --locked python scripts/prepare_runtime.py --output build/runtime
# 已构建时可加 --skip-build
```

输出目录必须不存在。缓存完整时可使用 `--offline`；可加 `--installed-env .venv` 复用依赖并对照锁文件检查。运行包只包含同平台 Python、联机服务、引擎、固定补位 AI、规则和渲染资源，不包含研究工具、模型或历史数据。

Linux 执行 `build/runtime/host.sh`；Windows 执行 `build\runtime\host.cmd`。Windows 包必须在 Windows 准备，Linux 包必须在兼容的 Linux 准备。

Windows 客户端与同平台主机包一同部署：

```powershell
powershell -File scripts/build-client.ps1 -QtPrefix C:\Qt\6.8.3\msvc2022_64 -Output build\host-dist -Runtime build\runtime
```
